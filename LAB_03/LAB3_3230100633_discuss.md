核心原因有两层。

第一层是 min < 0 的数学含义。你现在的滤波器在 LAB_03/LAB3_3230100633_debug.ipynb (line 1353) 里返回的是
min + (1 - min) * H_notch。
当 min > 0 时，notch 中心不会真正压到 0，只是“留一点残余频率”，所以对应的周期噪声没有被彻底去掉，空间域里就还会看到斜线。
当 min < 0 时，notch 中心附近会变成负值，这不只是衰减，而是把那部分频率“反相”了。反相会带来相位翻转，有时会把原来的残余条纹和滤波引入的振铃互相抵消，所以你看到伪影反而更少。但这更像“偶然抵消”，不是标准的 notch 去噪。

第二层是你当前 notch 的位置公式本身有问题，这很可能才是伪影的主要来源。你在 LAB_03/LAB3_3230100633_debug.ipynb (line 1360) 用了：

D_k1 = sqrt((U-u0)^2 + (V-v0)^2)
D_k2 = sqrt((U+u0)^2 + (V+v0)^2)
但你的频谱已经 fftshift 了，坐标是图像坐标，不是以 (0,0) 为中心的频率坐标。对称点不该是 (-u0,-v0)，而该是相对频谱中心的镜像点：

uc = height // 2
vc = width // 2
对称点应为 (2*uc-u0, 2*vc-v0)
也就是说，你现在第二个 notch 大概率没有打在共轭对称点上，只压掉了一侧频率。这样就容易在空间域产生斜线残影、振铃，随后 min < 0 的反相恰好帮你“补了一点”。

更好的做法：

把 min 固定为 0，不要用负值。
修正成“关于频谱中心对称”的双陷波。
优先用平滑 notch，比如 Gaussian notch 或 Butterworth notch，别用太硬的 ideal notch。
一次性在频域把所有 notch 相乘后再 ifft，比多次反复到空域再滤更稳。
notch 半径 D0 不要过大，只盖住白点及其很小邻域，否则会伤到真实结构。
用 log(1 + abs(F)) 只做显示，不参与滤波器设计。

def generate_notch_filter(shape, u0, v0, D0, n=4):
    M, N = shape
    uc, vc = M // 2, N // 2
    U, V = np.meshgrid(np.arange(M), np.arange(N), indexing='ij')

    u1, v1 = u0, v0
    u2, v2 = 2 * uc - u0, 2 * vc - v0

    D1 = np.sqrt((U - u1)**2 + (V - v1)**2)
    D2 = np.sqrt((U - u2)**2 + (V - v2)**2)

    eps = 1e-6
    D1 = np.maximum(D1, eps)
    D2 = np.maximum(D2, eps)

    H = 1 / (1 + (D0 / D1)**(2 * n))
    H *= 1 / (1 + (D0 / D2)**(2 * n))
    return H
